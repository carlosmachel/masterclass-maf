Um agente, três portas

Um processo ASP.NET Core expõe o mesmo trabalho por três protocolos. O Aspire sobe esse processo, a tela e um segundo agente (o Centro de Distribuição) num comando só.

PortaQuem chamaProtocoloQuem responde

"/oncall"um alarme de sensorAG-UIo plantão, um workflow que conversa com o CD por A2A
"/mcp"o Claude Code, o VS CodeMCPo mesmo analista, só leitura

var builder = WebApplication.CreateBuilder(args);
builder.AddServiceDefaults();
builder.AddDemoSources();                // dados: SQL + Foundry IQ, ou CSV + pasta local
builder.AddSecurity();                   // Prompt Shields
builder.Services.AddAGUIServer();

    AnalystAgent.Create(AnalystAgent.ChatClient(builder.Configuration), sp));
analyst.WithInMemorySessionStore(withIsolation: false);   // a conversa sobrevive entre requisições

var onCall = builder.AddOnCall();        // workflow do plantão
builder.AddAnalystMcp();                 // o analista como tool MCP

var app = builder.Build();

app.MapAGUIServer(analyst, "/").WithMetadata(DashboardMapping.Options());
app.MapAGUIServer(onCall, "/oncall").WithMetadata(DashboardMapping.Options());
app.MapMcp("/mcp");
app.Run();
sessãoWithInMemorySessionStore guarda a conversa inteira (histórico, aprovações pendentes, estado do agente) pelo threadId que a tela manda. Sem ele, cada requisição começa do zero. withIsolation: false serve para a demo, que tem um usuário só; com vários usuários, deixe o isolamento ligado e autentique, para ninguém retomar a conversa de outra pessoa.

O Aspire: a planta e o Run()

AddProject e AddViteApp só descrevem o que vai rodar. Quem sobe tudo é o Build().Run(): cada projeto vira um processo, com a porta e as variáveis de ambiente que você declarou. No .NET, LocalModel__Model vira Configuration["LocalModel:Model"]; o agente só lê configuração e não sabe que o Aspire existe.

var dc = builder.AddProject<Projects.Ipe_DistributionCenter>("dc");      // outro agente, outro processo

    .WithEnvironment("AZURE_TOKEN_CREDENTIALS", "dev")                     // só o az login, sem managed identity
    .WithEnvironment("LocalModel__Model", "qwen3-ipe-8b")
    .WithEnvironment("DistributionCenter__Url", "http://localhost:5180");

builder.AddViteApp("web", "../../web")
    .WithEndpoint("http", e => e.Port = 4280)
    .WithReference(agent)
    .WaitFor(agent);

builder.Build().Run();

00 · o fio condutor

Uma pergunta, do clique à tela

Toda cena é uma variação deste caminho. A tela faz um POST, o agente roda em streaming e cada pedaço da resposta volta como um evento AG-UI por Server-Sent Events.

sequenceDiagram
  participant V as Vue (useAgent.ts)
  participant H as MapAGUIServer
  participant A as Agente (Harness)
  participant M as Modelo
  participant T as Tool (C#)
  V->>H: POST threadId, messages, state
  H->>A: RunStreamingAsync
  A->>M: mensagens + schema das tools
  M-->>A: quero chamar GetFreezerStatus
  A-->>V: TOOL_CALL_START / ARGS / END
  A-->>V: STATE_DELTA (MapCall: passo rodando)
  A->>T: executa o método
  T-->>A: resultado (JSON)
  A-->>V: TOOL_CALL_RESULT
  A-->>V: STATE_DELTA (MapResult: KPI + passo feito)
  A->>M: resultado da tool
  M-->>A: texto da resposta
  A-->>V: TEXT_MESSAGE_CONTENT ...
  A-->>V: RUN_FINISHED

O modelo só decide o que chamar e escreve o texto. Executar a tool, guardar o histórico, converter tudo em eventos e montar a tela é código: do MAF ou seu.

As camadas do agente

O analista é um agente Harness embrulhado em camadas, como uma cebola. Cada camada é um decorator: recebe a chamada, faz a sua parte e passa adiante.

    Assemble(Harness(chatClient, sp, Instructions.Analyst, AgentTools.All(sp)), sp);

    new ErrorLoggingAgent(                                   // 4. registra a causa de erros no log

3. O resultado da tool desenha a tela

public static AGUIStreamOptions Options() => new AGUIStreamOptions()

// o passo de progresso tem a chave do CallId: o resultado fecha o passo certo
private static IEnumerable<BaseEvent> Start(FunctionCallContent call, string label) =>
    [Event([("/progress/" + call.CallId, new Step(label, "running", null, Now()))])];

4. O Vue aplica o patch

A tela inteira lê um único objeto de estado. Progresso, KPIs, gráficos, alertas e ações são caminhos dentro dele. O componente que lê cada caminho decide como aparece.

case 'STATE_DELTA':
  state.value = applyPatch(state.value, e.delta)

Zero token

O modelo não desenha tela. O painel se monta enquanto o agente trabalha.

Determinístico

O progresso não depende de o modelo lembrar de avisar.

Opt-in

erro de toolSe uma tool lança exceção, o modelo recebe só Error: Function failed., sem a mensagem da exceção (que pode ter connection string ou nome de servidor). Ele costuma tentar de novo. A causa fica no trace do Aspire.

O retrieve do Foundry IQ

Uma knowledge base do Azure AI Search sobre os documentos no Blob. A ação retrieve planeja as consultas, busca, reordena e devolve os trechos com as referências. O nome do arquivo citado vem das references, que são o valor exato do serviço, e não do texto que o modelo escreve.

src/Ipe.Agent/Knowledge/FoundryIqKnowledgeBase.cs
private readonly KnowledgeBaseRetrievalClient _client = new(searchEndpoint, knowledgeBase, credential);

public async Task<IReadOnlyList<Passage>> SearchAsync(string question, CancellationToken ct = default)
{
    var request = new KnowledgeBaseRetrievalRequest();
    request.Intents.Add(new KnowledgeRetrievalSemanticIntent(question));
    var response = (await _client.RetrieveAsync(request, cancellationToken: ct)).Value;

    // URL do blob → nome do arquivo
    var documents = response.References.OfType<KnowledgeBaseAzureBlobReference>()
        .ToDictionary(r => r.Id, r => Path.GetFileName(r.BlobUrl.AbsolutePath));
    // ... cada item [{ ref_id, content }] vira um Passage com o documento certo (até 3 trechos)
}

3. Dentro da tool, o filtro vale de qualquer jeito

A tool lê o estado da requisição atual pelo contexto da invocação, sem receber isso por parâmetro. O estado vem do navegador, então é validado como qualquer entrada externa.

src/Ipe.Agent/Dashboard/DashboardFilters.cs
public static Filters Current() => Read(FunctionInvokingChatClient.CurrentContext?.Options);

public static Filters Read(ChatOptions? options)
{
    if (!options.TryGetRunAgentInput(out var input) || !input.State.TryGetProperty("filters", out var f))
        return Filters.None;
    // só passam região da lista conhecida e IDs inteiros positivos
}

// o filtro da tela sempre vale; o que o modelo manda só soma
public static (string? Region, IReadOnlyCollection<int> Excluded) Combine(string? regionFromModel, int[]? excludedFromModel)
{
    var dashboard = Current();
    return (dashboard.Region ?? regionFromModel,
            (excludedFromModel ?? []).Union(dashboard.ExcludedStoreIds).ToList());
}

O front espera todos os cards

O modelo pediu as três ações na mesma mensagem. Para chamá-lo de novo, toda chamada de tool precisa de um resultado, executado ou rejeitado. Por isso as decisões voltam juntas, num único resume.

web/src/App.vue · web/src/agui/approval.ts
function decide(interrupt: Interrupt, approved: boolean) {
  decisions[interrupt.id] = approved
  const pending = agent.interrupts.value.filter((i) => !(i.id in decisions))
  if (pending.length === 0)
    agent.resolveInterrupts(agent.interrupts.value.map((i) => ({ interrupt: i, approved: decisions[i.id]! })))
}

// approval.ts: a decisão leva a chamada original que o modelo fez
const payload = {
  approved,
  toolCall: { callId: interrupt.toolCallId, name: toolCall.name, arguments: JSON.parse(toolCall.args) },
}
return { interruptId: interrupt.id, status: 'resolved', payload }

cena 5 · o ataque ao vivo

Um documento envenenado na base

tópico técnicoMiddleware contra prompt injection

Um comunicado de fornecedor entra na base de conhecimento. No meio dele, um comentário HTML, invisível no preview do Markdown, traz uma ordem dirigida ao assistente: criar um pedido de R$ 1.200.000,00 sem pedir confirmação. Isso é prompt injection indireta: o ataque não vem de quem digita, vem de uma fonte que o agente consulta.

O middleware fica entre a tool e o modelo

A pergunta do usuário é inocente. O texto não confiável chega no resultado da busca, então a checagem fica ali: um middleware de function calling roda em volta de cada execução de tool.

src/Ipe.Agent/AnalystAgent.cs · Security/DocumentShield.cs
harness.AsBuilder()
    .Use(sp.GetRequiredService<DocumentShield>().InvokeAsync)
    .Build()

public async ValueTask<object?> InvokeAsync(AIAgent agent, FunctionInvocationContext context,
    Func<FunctionInvocationContext, CancellationToken, ValueTask<object?>> next, CancellationToken ct)
{
    var result = await next(context, ct);                          // a tool roda
    if (context.Function.Name != "SearchKnowledgeBase") return result;

    var attacks = await shields.DetectDocumentAttacksAsync(question, texts, ct);
    Activity.Current?.AddEvent(new("prompt_shields.attack_detected", ...));   // aparece no trace

    // o trecho atacado vira aviso de quarentena: o modelo nunca lê a instrução
    return passages.Select((p, i) => attacks[i] ? p with { Text = Quarantine, Blocked = true } : p).ToList();
}

O que sobra

Um pedido legítimo, justificado por vendas e estoque, com nada do comunicado. E ele ainda pede aprovação.

defesa em camadasSem o Shields, o modelo pode obedecer ou não, e isso muda de versão para versão. A aprovação humana segura uma ação sem humano; o Shields impede o ataque de chegar ao modelo. Esconder ou trocar o nome da tool não protege: o modelo entende a intenção, e um atacante que descobre o nome real volta a ter sucesso.

Triagem e fechamento são regras; só o passo do meio precisa de julgamento. Um alarme falso morre na triagem, sem gastar tokens, e a ordem dos passos é o grafo, não um pedido no prompt.
